# Техническая спецификация

## Назначение

Планировщик путешествий принимает параметры поездки и возвращает маршрут по дням,
известную часть сметы, ссылки на источники и оговорки о неполных данных.
Установка, подключение сервисов и запуск описаны в [README](README.md).

## Архитектура

React → FastAPI → run_trip → CrewAI (Process.sequential).
Команда состоит из исследователя направления, специалиста по бюджету и планировщика.
Результаты исследования и сметы передаются в контекст следующих задач.
Инструменты: поиск Tavily basic, чтение публичных страниц и Decimal-калькулятор.
Каждая поездка исполняется в отдельном управляемом spawn-процессе.

## Данные и проверки

- Вход TripInput: город отправления, направление, даты, бюджет с валютой,
  количество путешественников и интересы.
- Результаты: ResearchResult, BudgetResult и ItineraryResult из models.py.
- Денежные значения сериализуются десятичными строками. Все расходы относятся
  ко всей группе и всей поездке; конвертации валют и повторного умножения нет.
- Неизвестные суммы остаются null. known_total — известный подытог;
  complete=false и budget_status=undetermined не подтверждают соблюдение бюджета.
- Pydantic и программные guardrail проверяют структуру, даты, валюту, источники,
  выбранные места и согласованность результатов. Проверки качества учитывают
  плотность программы, питание и отсутствие повторов.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /health | Доступность сервера без проверки внешних сервисов |
| POST | /trips | Создание поездки, ответ 202 с id и адресами состояния/результата |
| GET | /trips/{id} | Состояние и события выполнения |
| GET | /trips/{id}/result | Результат завершённой поездки |

Состояния: queued, running, completed, failed. Неизвестный id — 404;
недоступный результат или занятый слот — 409. Параллельные поездки не допускаются.

## Эксплуатация

- Локальный API: один worker, без reload во время поездки, без авторизации и БД.
- История HTTP хранится в памяти и теряется при перезапуске; отчёты остаются в results/.
- Лимиты по умолчанию: 420 секунд на поездку и 24 обращения к LLM;
  до 12 000 выходных токенов и 90 секунд на запрос полной Crew.
- Настройки LLM задаются через LLM_PROVIDER, LLM_MODEL, LLM_API_KEY и LLM_BASE_URL.
  Ключ поиска — TAVILY_API_KEY. Локальный .env исключён из Git.
- Клиент получает только публичный адрес API, ограниченные события и результаты.
- Цены, часы работы и расписания могут быть оценочными. Проверки согласованности
  не гарантируют фактическую актуальность сведений. Бронирование и оплата отсутствуют.

Подробности сопровождения: [руководство разработчика](docs/DEVELOPMENT.md).

## Автоматические проверки

GitHub Actions (.github/workflows/ci.yml): push, pull_request и ручной запуск.
Python 3.12 на Windows: установка приложения с test extra, pip check и unittest.
Node.js 26 на Ubuntu: npm ci, frontend-тесты, TypeScript и production build.
Секреты и реальные запросы к LLM/поиску не используются. Workflow имеет права
только на чтение содержимого репозитория; Actions закреплены по SHA.
